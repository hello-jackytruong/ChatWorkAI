# Independent implementation review

Date: 2026-11-23. Scope: pending tracked/untracked Zalo-media implementation in `feat/zalo-account-media-r2`, against the approved 24-requirement plan and scope-and-design contract. Implementation was actively changing during review; this records observations before controller fixes, not approval of the final revision. No implementation files edited, no live DB/provider/R2 calls or heavy typecheck run.

## Blocking findings

1. **High — inbound attachment binding uses incompatible slot contracts.** `apps/zalo-account-gateway/src/runtime/provider-message.ts:218` emits original slot `original`; `packages/business/src/media/zalo-account-capture.ts:66` indexes attachments using `Number(descriptor.slot)`. This produces `NaN`, so original references have no attachment ID, while `packages/business/src/message/list-for-conversation.ts` projects URLs only by matching attachment ID. A live DM/group photo/file can be stored successfully yet never render. Map descriptor role/provider slot to the current attachment explicitly; test normalized gateway input through capture and conversation response. Controller notified and fixing.

2. **High — default-disabled deployment hides existing attachments.** `packages/business/src/message/list-for-conversation.ts:28` blanks every Zalo URL/fallback/origin unconditionally. With default-off capture and no ledger references, all existing photos/files lose their display URL immediately, including trusted internal storage objects. Preserve authorized legacy internal-object resolution and an existing safe fallback while excluding raw provider URLs and deleted parents. Verify flag-off, legacy internal key, legacy remote key, stored archive, and deleted-parent cases.

3. **High — contact deletion retains private archives forever.** `packages/business/src/contact/service.ts:819` records ordinary MessageCleanup and deletes the contact without releasing any Zalo media reference. The new tables deliberately have no parent FK. `releaseOwners` has only a workspace-purge caller (`packages/business/src/zalo-account-media/purge.ts:25`), and deletion maintenance only selects assets already closing/deleting. Thus a contact purge leaves live archival references and object manifests indefinitely, and cannot reach zero-reference deletion. Add bounded scoped release by contact-inbox/conversation ownership in the existing deletion flow, then grace/zero-ref cleanup; preserve shared sticker references. This is retention completeness, not a demonstrated new download authorization bypass: current message reads reject missing contact inboxes.

4. **High — non-message resources cannot use the promised public operations.** `apps/builder/src/features/zalo-accounts/api/media.ts:24` requires conversationId for every operation; `packages/business/src/zalo-account-media/read-service.ts:89` restricts all currentRows to message owners. Captured account/group/contact avatars and covers therefore cannot be listed, inspected, retried, or downloaded by an authorized channel manager. The approved contract explicitly covers management-authorized current non-message owners. Add a separate strictly authorized owner branch through the same service; reject inbox-only callers for management resources.

5. **High — positively completed reserved uploads have no crash-repair path.** `apps/worker/src/zalo-account-media/maintenance.ts:18` invokes only recoverUnstarted; repository recovery (`packages/database/src/repositories/zalo-account-media/repository.ts:102`) excludes every reserved candidate key. A process death after successful PUT but before complete leaves a downloading lease forever, even when HEAD can positively establish the immutable object. `claimDeletion` rejects retained lease tokens (`repository.ts:894`). Persist expected candidate size/checksum and provide bounded positive-HEAD CAS adoption when the generation/reference remains active. Do not interpret missing HEAD, lease expiry, abort, or storage outage as proof the old PUT cannot still complete. Unknown outcomes must remain purge-incomplete under the approved safety contract. A definite provider storage rejection should be distinguished from ambiguous network termination only if its no-write semantics are verified.

## Safety observations and limitations

- The CDN downloader applies a host allowlist, rejects private DNS answers, pins the validated address for HTTPS, validates redirects again, bounds content length/stream bytes, and uses abortable deadlines. No concrete SSRF bypass found in the inspected transport.
- Fresh archived-message signing checks current Message timestamp/conversation/deletedAt and current account inbox binding. No concrete cross-workspace/private-key response leak found on those paths.
- DB lease expiry cannot fence an already-issued S3 PUT. Retaining the manifest and reporting incomplete is correct when remote outcome is unknown. A HEAD absence is not quiescence proof; do not repair this by blindly expiring tokens then deleting objects.
- Generic API retry resets attempt counters intentionally; route text currently says exhausted resources are not reset, which contradicts repository retry behavior. Align the documented reset policy with the accepted explicit-retry contract.
- Profile-source revisions and canonical alias rebinding need final-revision regression checks after controller changes. Superseded assets remain active and unreferenced unless an explicit cleanup admission is added.
- No coverage/type/lint percentages are claimed. Focused tests and final gate remain controller-owned; final release approval also requires the plan staging/provider/private-bucket checks.

## Follow-up source review — controller fixes in progress

The original findings above are historical observations; use this section for their current disposition.

- **Inbound attachment slot binding: closed in source.** Capture now distinguishes numeric attachment slots from gateway role slots, matches source URLs, and binds the single legacy attachment for original/thumbnail/poster roles. The controller reports RED/GREEN coverage; this reviewer did not rerun it.
- **Default-disabled legacy rendering: closed for the reported case in source.** `withResolvedAttachmentUrls` enables private redaction when a ledger projection exists, capture is enabled, or the parent is deleted. Flag-off legacy rows without a ledger use the existing resolver. Existing private archived rows remain signed through scoped ledger projection.
- **Non-message public media operations: closed in source for account/group/contact/sticker owners.** API authorization chooses conversation inbox scope versus explicit owner channels-management scope. The service checks the current account/group/contact owner before resolving scoped references; repository filtering now applies ownerKind/ownerId before pagination.
- **Positive-HEAD candidate crash adoption: substantially addressed in source.** Worker verifies bounded size, MIME family, and checksum metadata versus immutable-key checksum before CAS adoption. Expired candidate enumeration now includes both downloading and failed retained leases. Adoption preserves the original lease/uncertainty, so it does not falsely authorize deletion. The controller is completing closing-generation settlement; final verification remains required.
- **Contact deletion cleanup: partially implemented in source.** Contact.delete now calls a bounded lifecycle release inside its existing transaction; orphan admission uses a separate zero-reference grace period. Remaining-ref continuation through MessageCleanup is being wired. Two concrete SQL problems found in that new continuation query were immediately reported to the controller: nonexistent `ContactInbox.workspaceId`, and bigint conversation IDs aggregated into JSON numbers instead of text (precision loss). Verify both before treating this closure as complete.

### Additional concrete follow-ups

1. **High — QR capture failure after commit cannot repair on replay.** `packages/connections/src/connect-targets.ts` commits `connectAndPersist`, then separately calls `saveAuthorization` (which can throw during media registration). Retry hits the already-active duplicate guard before capture. The reconnect path commits session completion before the new save/capture call; trusted-device replay returns completed session without revisiting capture. Persist the avatar intent in the same existing main-DB commit through a tx-aware hook, or provide a durable same-session repair path. Swallowing the error would lose the required capture durability.
2. **Medium — orphan grace can use an obsolete zero-reference observation.** `admitOrphan` records closingAt on the first zero-ref observation; register currently reattaches an active generation without clearing it. An asset orphaned at t0, reattached at t12h and detached at t25h can be deleted immediately using t0 rather than receiving a fresh 24-hour grace period. Reset closingAt when a live reference attaches under the existing shared lock. Test the reattach/detach cycle.
3. **Medium — uncertain candidates can starve later recoverable candidates.** `expiredLeases` repeatedly selects the oldest 50 with no progress cursor or next-verification timestamp. Fifty permanently uncertain candidates (correctly retained after HEAD absence) block examination of a 51st positively completed one forever. Rotate a bounded cursor or persist next inspection time without settling uncertain writes. Likewise deletionPage's first 100 unclaimable rows can block later claimable deletions.
