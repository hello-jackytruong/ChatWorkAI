# Scope and design contract — Zalo Account media R2/S3

Status: proposed design for review; implementation not started. Date: 2026-11-23.
Project root: `/Volumes/DevSSD/Work/GitHub/ChatWorkAI`.

## Outcome and boundaries

Deliver every item in `docs/zalo-account-checklist.md`, section **P0 · 2**: durable originals and useful resource variants in private R2/S3, bounded resource consumption, status/retry, secure reads, existing-data backfill, reconciliation and retention-safe cleanup. Preserve current other-channel behavior. Planning scope is HOLD SCOPE, not a reduced MVP.

Non-goals: new history crawler, new video/voice send API, sticker picker/player UI, profile editor, socket redesign, native revoke/delete operations, recalled-content viewer, generic media framework, FFmpeg service, new container or broad Attachment/Message migration. Storage extraction of already-arriving types IS in scope; unsupported current display does not justify discarding available bytes. Existing supported Inbox fields continue to display media after storage; no new media presentation features are implied.

Acceptance: all 24 checklist lines map to one of four phases and a RED test; bytes, identity, original immutability, authorized reads, crash repair and bounded purge work for live/echo/group/current history-shaped inputs. Existing history import does not exist: provide the reusable ingestion path and backfill stored rows, not a provider crawl. Source absent/expired is an explicit truthful state, never fake archival success. Current `[x]` items remain regression constraints, not assumed storage of true originals before any old compression.

## Chosen shape and alternatives

Use **two small Zalo-only main-DB tables** (`ZaloAccountMediaAsset`, `ZaloAccountMediaReference`), **one media business service**, and **one dedicated queue hosted by the existing low worker process**. Existing queue infrastructure, uploader, signing, image encoder and shard repository remain owners of their current responsibilities. No new long-running process/container, generic event bus, distributed semaphore framework, bucket or mandatory third-party package.

The asset row is the durable outbox; the reference row maps message/profile/sticker owners to assets. Separate cardinalities are justified by account-local sticker reuse, source revisions, canonical echo rebinding and reference-safe purge. Do not add a separate generic job/outbox/run table. No cross-workspace/account physical deduplication. Ordinary message originals are ownership-scoped; only explicit same-account resources (e.g. same sticker variant) share an asset. Existing media-library/public-send objects remain owned by their existing subsystem: copy/adopt a private archival original, never delete the source just because a Zalo ref disappeared.

Rejected alternatives: (1) add Zalo to generic Meta/WA hydration: changes current semantics, buffers, optimizes original and lacks Zalo refresh strategy; (2) enqueue all downloads on shared low concurrency=30: steals receipt/echo capacity; (3) direct multipart pipeline: more abort/recovery complexity than needed under bounded file sizes; (4) one per-owner table: simpler initially but duplicates cached sticker bytes and cannot cleanly transfer owner references after canonical merge. The chosen seam costs two small tables/one queue; remove these Zalo-specific additions without changing other channel adapters if abandoned.

## Persistence contract (proposed, no DDL executed)

Asset: shared columns, workspaceId/accountId with indexed FKs, resource identity hash, kind/role, provider resource identity/version where known; encrypted source locator and source revision (rotating URL is not identity); observedAt/providerExpiresAt nullable; enum state pending/downloading/stored/failed/expired; attempts/lastAttemptAt/nextAttemptAt/errorCode; claimToken/leaseUntil; candidateObjectKey/checksum/size/MIME; final objectKey/checksum/size/MIME; optional width/height/duration with provenance (provider/detected/unknown); original filename; uploadedAt; projected/reconcile metadata; deletionPhase enum none/candidate/closing/deleting/confirmed plus deletionToken/deleteAfter/closingAt (separate from five storage states). `failed` means terminal/retries exhausted, `expired` requires positive source-gone evidence; generic forbidden 403 is failed/forbidden unless expiry is proven.

Reference: shared columns, workspaceId/accountId/assetId indexed FKs; ownerKind (message/account/contactInbox/group/member/sticker), owner identity hash, slot, role, owner/source revision, source/provider message IDs where relevant; nullable conversationId/contactInboxId/messageId/messageCreatedAt/attachmentId/attachmentCreatedAt as pointers (no cross-shard FKs); projection state and last error. Unique owner+slot+role+revision, with explicit current reference selection. Index message/attachment pointers and owner lookups. Every query scoped by workspace and account. Partial due/lease/reconciliation/deletion indexes prevent whole-table scans.

No schema change to compressed/sharded Message/Attachment; use existing original/thumbnail/name/size/dimension fields for display. Narrowly add thumbnail/name to `UpdateAttachmentParams` only if needed, update every implementation/caller with tests. Duration/checksum/state/source locator live in Zalo tables, not generic attachment DDL. Main DB and shard writes are NOT atomic: pre-register intent before message ACK, bind after shard persistence, idempotent recovery after every boundary, and store projection status separately from byte-storage success.

Natural identity: workspace + account + thread type/thread ID + provider message ID + stable provider attachment ID or deterministic payload slot + resource role. Temporary local outgoing identity gets aliases to confirmed provider IDs. Profile owners additionally have source revision; an old completion cannot replace a newer avatar. Sticker cache uses account + category + sticker + variant + provider version when supplied. Never use expiring URL tokens as identity or raw provider strings as filesystem/object paths.

Archive message keys: `workspace/<workspaceId>/zalo-account/<accountId>/conversations/<conversationId>/assets/<assetId>/<role>/<sha256>.<safeExt>`. Bind the validated conversation ID before transfer; pending intent may precede that binding. Profile/sticker/shared resource keys use `workspace/<workspaceId>/zalo-account/<accountId>/resources/<ownerKind>/<ownerHash>/<assetId>/<role>/<sha256>.<safeExt>`. Original and derivatives differ; no `public/` archive original. Stage checksum/candidate key in ledger before PUT; retries HEAD and validate actual size + our SHA metadata (ETag is not checksum) before finalizing. A lease-lost worker cannot finalize or project. An extra object written by a stale worker is a cleanup candidate after grace, not a replacement original.

## Transport and resource budgets (proposed defaults, not provider quotas)

Use worker-only Node HTTPS transport with validated/pinned DNS lookup per connection/redirect, normal TLS hostname verification, HTTPS only, no URL credentials, port 443, configured vetted exact/suffix CDN host rules, reject any private/loopback/link-local/reserved A/AAAA answer, including mapped IPv6. Validate redirect targets and cancel bodies; no arbitrary card/link webpage fetches. Node-only downloader never enters builder router graph. Provider fixture host inventory is a release gate; unknown hosts fail explicitly until reviewed.

Stream response into a task-owned mode-0600 spool under one dedicated temporary directory, with running byte/hash/magic-prefix checks and backpressure. Request identity content encoding; reject unexpected encoding rather than trusting compressed length. Hash before PUT, then upload a `createReadStream` with actual ContentLength through `Uploader.putObject`, signal and private ACL where supported. No direct `arrayBuffer`, full original Buffer or new multipart uploader. No multipart uploads are created by this feature; existing deployment multipart lifecycle rules remain unchanged. `finally` removes temp files, shutdown aborts active work, bounded age-based scavenging repairs crash leftovers.

Default one transfer cluster-wide, BullMQ `setGlobalConcurrency(1)` (installed Queue API verified) and worker concurrency=1, hosted as subconsumer in `apps/worker/src/low/worker.ts`, using existing shutdown/blocked-owner wrappers. Do not change shared LOW/HEAVY concurrency. Live originals priority=10, previews/resources=20, backfill=30; producer adds at most50 jobs/tick with <=50 waiting/delayed outstanding transfers across this queue. Promote a waiting resource/backfill job aged>=5min to priority10 (preserving original enqueue time); fair per-account selection alone is not execution fairness. Pending DB rows carry excess backlog, not unbounded Redis jobs. Test continuous live arrivals and actual aged execution across replicas. Named server-only switch `ZALO_ACCOUNT_MEDIA_STORAGE_ENABLED` defaults false; one media policy accessor is shared by registrar/worker/recovery. Global disable stops new transfers but leaves stored reads available; worker checks switch at claim and before write.

Budgets: image/GIF 10 MiB, file 25 MiB, video 64 MiB, audio 16 MiB, avatar/cover/thumbnail/poster 2 MiB, sticker variant 8 MiB; <=12 declared resources/message, <=3 variants/sticker. Per-origin deadline 60s including redirects; connect/idle timeout 10s; <=3 redirect hops. Retry maximum 5 attempts, exponential 30s base, Retry-After respected with max15min and jitter. One empty HTTP200 gets one bounded retry (ZaloCRM fixture clue), not unlimited success. Timeout/408/429/5xx/storage transient retry; host rejection/oversize/MIME rejection terminal; 404/410 source gone => expired. Retry and recovery are DB-driven; Redis retention does not own correctness.

Original transfer target: constant-memory streaming, no allocation proportional to a 64 MiB video; disk peak <= one largest original plus one bounded image derivative workspace (~96 MiB target at default concurrency), not a promise about total Node RSS. Metadata header inspection <=256 KiB. One image encode at a time under existing encode limits and a pixel cap; no video decode/transcode/FFmpeg. Store provider duration/dimensions with provenance; missing/unsupported duration stays null, not zero. Download supplied poster/thumbnail. Generate image preview only using existing bounded encoder into a separate key; animated originals remain intact. Preflight actual resource usage during staging; reduce ceilings or stop if measured budgets fail, never silently increase shared worker concurrency.

## Ingress, original protection and canonical echo

Split typed inbound media descriptor from strict outbound attachment schema; outbound image/file capabilities/limits do not change. Add the descriptor array to BOTH direct/group event envelopes and update their inbound content-admission refinements so descriptor-only voice/video/sticker survives gateway validation and serialized transport without legacy text/attachments. Extract image/file/video/audio/GIF and validated card-media roles from known provider shapes/params, not recursive URL crawling. Keep display compatibility for types UI already supports. Unknown display types get storage descriptor/reference without enabling new send capabilities. Collect avatar URLs from existing connect/friend/group sync paths, including `zaloAccountService.saveAuthorization` for initial connection/reconnect; friend/group sync alone cannot cover account avatars. Preserve member avatar/cover only when supplied by those payloads; never crawl members/profile APIs. For incoming sticker IDs without URLs, add only a bounded gateway metadata command using `getStickersDetail` (batch<=20, account-scoped cache), no picker/search/new send APIs.

Register durable asset/reference intent before event ACK and before group `markPublished` clears payload. Group policy must admit persistence first; send-only/disabled incoming groups must not create unauthorized archives. Duplicate/replayed events repair intents even if Message already exists. Original source fields are internal, encrypted; public response strips locators. DB registration failure cannot silently ACK/drop durability; queue publication failure is repaired by indexed outbox recovery. Avoid holding the gateway event stream while bytes download.

Protect original bytes at the **earliest** Zalo-specific outgoing upload/ingest seam: `packages/business/src/message/create-outgoing.ts` for Inbox/device/media-library uploads AND canonical-send for API URL sends, before any later/shared image optimization. Current filesystem upload helper itself uploads original bytes; do not refactor it on an unproven synchronous-compression assumption. Distinguish source admission: provider locators use vetted CDN transport, while outgoing archives copy/read the actual trusted ChatbotX-uploaded object identified by scoped Attachment, not the caller URL. Existing public-URL send contract remains unchanged. If checksum is absent, stream the internal object once through bounded hash/spool; never treat ETag as SHA. Mark new Zalo archival targets `keepOriginal` where existing fields apply; do not change optimizer defaults or file handling for other channels. Reused media-library files copy current source bytes and report provenance; do not claim recovery of an original already overwritten historically. Existing queued optimizer jobs must recognize protected Zalo private keys/targets; a producer-only skip is insufficient. Derivative is a separate object, never overwrites original or is sent in its place unexpectedly.

`reconcileOutgoingSourceId` currently deletes duplicate echo Attachment/Message rows. Do not pretend its shard transaction can atomically update main-DB media tables. The Zalo business send path MUST durably register aliases/reference rebinding before destructive reconciliation and carry enough stable provider/local identity to repair projection after either commit. Own BOTH destructive call sites: shared chat send reconciliation and group-inbox reconciliation. The group path currently opens a main-DB transaction before calling the shard; commit the media alias/rebind intent in a separate short main-DB transaction BEFORE entering the outer destructive workflow, not in a transaction that could roll back after shard deletion. Persist provider/local alias and source owner data before deletion; if durable registration fails, do not delete the echo. Prefer Zalo business orchestration hooks; if repository opt-in is required, default off and prove all non-Zalo callers unchanged. Jobs read current references, never trust an ephemeral echo attachmentId in payload. Stored original survives duplicate echo deletion; failed outgoing message semantics remain as existing product rules (do not reclassify failed sends as delivered).

## Reads, maintenance, retention

Message/profile reads batch-resolve references and use existing signed URL conventions. Do not replace `avatarUrl` with an unsigned object key. Stored images/files render through current attachment UI; pending/failed state is exposed via Zalo media API and existing safe fallback, without raw provider URLs. No N+1 HEAD/network/provider requests during conversation read. Signed URLs are short-lived bearer credentials (proposed5min); already issued URLs may remain valid until expiry. Do not promise instant revocation without a proxy.

Proposed public operations under `features/zalo-accounts/api/` all share the media service: list/get media status; authorize download by media-reference ID; retry an eligible media item; POST bounded existing-row backfill; POST dry-run-first reconciliation. Read/download scope must enforce account + conversation/owner access, not `channels` token alone (follow message `inbox` and member-scope contracts); admin maintenance uses channels-management authorization and cannot accept arbitrary URL/objectKey/workspace. Token read-only cannot mutate. The new media download endpoint AND Zalo-specific normal attachment projection must load the current parent Message and refuse fresh signing if deletedAt is set or the parent is missing. Current UI hiding does not enforce this authorization. Preserve bytes; a separately authorized retained viewer belongs to P0·3. Already-issued signed bearers remain valid until TTL; do not claim instant revocation.

Backfill only persisted supported URL-only Attachment/profile references; account + bounded time/conversation window, keyset cursor (includes shard timestamp), limit<=50 per request. Response carries nextCursor and counts; rerun is idempotent through natural asset identity, no new global run table. No Message history fetch. Reconcile DB->object HEAD page<=50, object->DB prefix-limited list<=100 with continuation + max runtime. Default dry-run. An orphan delete requires no references, no live claim, >=24h grace, a second independent confirmation and durable deletion intent. DB/storage outage never counts as absence.

Provider undo alone retains media; no UI/revoke behavior change here. Contact/inbox/account/workspace purge removes only authorized owners, then unused assets after durable deletion scheduling. Existing shared objects require reference checks. Registration and deletion claim must lock the same asset row: zero-ref deletion marks a deletion token/generation; registration cannot attach to that deleting generation and must create a next generation. Perform HTTP DELETE outside the transaction and finalize by token CAS. Enter a durable closing barrier before purge, abort in-flight work and preserve asset/claim/deletion manifest while any old PUT generation or remote outcome is uncertain. DB lease loss alone cannot prevent a delayed S3 PUT. Parent purge returns WorkspacePurgeIncompleteError and must not cascade away this manifest; verify/compensate any late object before marking storage cleanup confirmed. Before-HTTP lease checks, upload deadlines, and after-response compensation are required. If finite quiescence cannot be established, retain the barrier/manifest and report incomplete rather than asserting deletion success. Purge batches<=100; network outside DB transaction; stop before parent purge deadline and resume on transient failure. Ordinary disconnect keeps archive; existing teardown preserves account metadata. Profile revisions can release obsolete unreferenced cache entries after grace; referenced sticker assets cannot be evicted solely by cache TTL. Never activate/refactor generic MessageCleanup cron in this task.

## Scope extension trace

Two real variants: direct and group messages share descriptor/asset/ref/download contracts. Only registration/auth/policy and owner projection differ; no separate DM/group downloader. Third already-present variant: account/group avatars use same byte-store with different owner reference/CAS, no Message/Attachment row. This justifies ownerKind+role but not a generic cross-channel registry. Existing Messenger/WhatsApp is a regression comparison, not a new variant to migrate.

## Release gates

Generate and inspect additive migration during implementation only; never apply `db:migrate` without explicit approval. Private bucket/reader staging preflight, actual pinned provider fixtures for extra resource types/CDN hosts, representative storage aborts, historical shard routing and echo races are required before flag-on. Plan writing runs none of these production/DB operations. Use feature disabled by default; additive rollout code remains able to read private stored keys after disabling writes. Do not drop tables/delete archive on rollback.

## Review notes

All numeric limits above are proposed technical budgets that should be tested; none is represented as a Zalo platform guarantee. No scope item is completed by merely retaining a provider URL. Where the provider supplies no source, return source_missing and keep the item incomplete until a fixture proves the capture path.

## Evidence-backed review deltas

- Group media alias intent must commit outside/before the outer main-DB transaction that invokes shard echo deletion; cover both shared-send and group call sites.
- Deletion admission and new shared-resource reference registration serialize under one asset lock/generation.
- DB lease fencing does not fence remote PUT; purge remains incomplete with durable manifest while late-write outcome is uncertain.
- Real queue aging and an outstanding backlog cap supplement per-tick dispatch limits.
- New signing requires a live, non-deleted parent; UI hiding alone is insufficient.

### Bounded implementation clarifications

- Private archive copies do not retroactively make existing `public/` send/media-library objects private. Preserve their current lifecycle/URLs; do not claim immediate revocation of those existing copies. New archive read endpoints must not expose them as a bypass.
- Temporary scavenging uses a dedicated namespace, active-lease exclusion, age threshold and streaming directory iteration bounded per tick; it never scans/deletes arbitrary /tmp files.
- Registration-time closing checks prevent new same-generation references; purge cannot finalize while remote operation uncertainty persists. An unbounded suspended process is not considered proven quiescent merely because its DB lease expired. Such cases remain incomplete and need operational quiescence/compensation proof before deletion is reported complete.
- One media policy accessor owns the default-off switch/limits; Node-only transfer and image encode code is not exported into builder imports. No new shared HTTP or S3 uploader behavior is changed.

## Proposed API contract detail

Routes below do not exist yet; this is the implementation contract for Phase3. Do not create a third operation ledger just for these naturally idempotent state/registration operations.

| Procedure / route | Input boundary | Output / authorization |
|---|---|---|
| listMedia — GET `/v1/zalo-accounts/{accountId}/media` | account from route, owner filters, signed cursor, limit1–50 | bounded rows with referenceId/kind/role/state/projection/errorCode/actual metadata; no locator/claim/objectKey; inbox scope for message rows, channel-management authority for account resources |
| getMedia — GET `/v1/zalo-accounts/{accountId}/media/{referenceId}` | reference ID, never arbitrary object key | safe status/detail only after workspace/account/current owner access |
| authorizeMediaDownload — GET `/v1/zalo-accounts/{accountId}/media/{referenceId}/download` | reference ID, variant role enum | `{url, expiresAt, fileName, mimeType}` only when stored and authorized; message scope+current parent not deleted, or current non-message resource owner management authority; no signing for missing/deleted parent |
| retryMedia — POST `/v1/zalo-accounts/{accountId}/media/{referenceId}/retry` | reference ID + expected source revision; bounded explicit reset policy | `{accepted,state,nextAttemptAt}`; CAS no-op when already pending/downloading/stored, no duplicate job; revision mismatch conflict; POST rejects read_only token |
| backfillMedia — POST `/v1/zalo-accounts/{accountId}/media/backfill` | bounded time/conversation window, signed continuation, limit<=50, dryRun defaulttrue | `{examined,registered,alreadyRegistered,skipped,nextCursor,complete}`; complete means only selected stored-row window, never whole Zalo history |
| reconcileMedia — POST `/v1/zalo-accounts/{accountId}/media/reconcile` | direction enum, bounded cursor, dryRun defaulttrue; account-derived prefix only | bounded findings, continuation, scanned counts; apply mode repairs/marks with CAS. Object deletion requires preview candidate IDs/version proof, no-live-ref/deleting generation and Phase4 grace checks; never broad delete-by-prefix |

Member callers use existing resolved workspace/member/conversation scope; workspace API tokens retain established workspace-level semantics but require the operation's declared inbox/channels scope. No raw User secret projection. Read-only tokens may inspect/download authorized stored files, never retry/register/reconcile apply. All private callers invoke the same media service, never a separate query implementation.

One immutable message original may have several provider message aliases from one outgoing command. Reference lookup must follow those aliases and original slot/role, not assume result.messageIds[0] owns every attachment. Tests include text+image split result and duplicate echo variants; no album sending or new outbound capability is added.

`source_missing` is an error/reason code, not a sixth storage state: where an expected asset has no locator, expose failed+source_missing with no transfer. A conditional resource that is not supplied/consumed schedules no asset. Physical deletion lifecycle uses deletionPhase, not an invented storage enum value deleted.
