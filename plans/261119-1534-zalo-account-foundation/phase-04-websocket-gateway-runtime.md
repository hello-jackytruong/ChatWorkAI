# Phase 4: WebSocket gateway runtime

## Outcome

Create `apps/zalo-account-gateway` as the only process allowed to load
`zca-js` and own personal-Zalo WebSockets. It exposes an in-process runtime port
for QR/reconnect/stop and emits typed lifecycle events to a sink port that item
5 will later connect to Redis/BullMQ. The app is horizontally scalable now,
without prematurely implementing that transport.

## Runtime invariants

- One account → at most one active SDK listener across replicas.
- Each locally replaced runtime receives a monotonically increasing epoch;
  callbacks from older epochs are ignored.
- Each distributed owner holds a renewable lease with a fencing token;
  losing renewal immediately stops the listener and blocks later publishes.
- Manual stop never schedules auto-reconnect. Passive close uses bounded retry;
  repeated failure emits `reauthorization_required` and stops.
- Reconnect must verify `getOwnId() === stored zaloUid` before the listener is attached.
- Secrets and QR images are never logged.

## Tests Before

1. Write a fake-clock lease test for two gateway instances racing: one acquires;
   only owner+fence can renew/release; after expiry a new, higher fence wins.
2. Write a runtime test that losing the lease stops the listener and suppresses
   all later SDK callbacks/events from the stale fence.
3. Write epoch tests: duplicate active commands coalesce; a fresh runtime after
   stop receives a higher epoch; old generated/scanned/closed/resolve callbacks
   cannot mutate the new runtime.
4. Write QR tests for generated, scanned, credentials, success, maximum three
   SDK retries, and fresh-session-required after exhaustion.
5. Write reconnect tests for success, UID mismatch, passive-close backoff,
   five closes in five minutes circuit break, and no reconnect after manual stop.
6. Write shutdown/readiness tests: Redis loss makes readiness false; SIGTERM
   drains listeners, cancels timers, releases owned leases, and closes clients.
7. Write a logging test that captures structured logs and asserts no auth fields,
   cookie values, QR image, IMEI, or user-agent value appears.

## Implementation Steps

1. Scaffold the app using the existing realtime/javascript-executor build,
   env, logging, and shutdown conventions. Add `zca-js` with a filtered install:

   ```bash
   pnpm add --save-exact zca-js@2.1.2 --filter zalo-account-gateway
   CI=true pnpm install --no-frozen-lockfile
   ```

2. Define ports:
   - `RuntimeCommandPort`: start QR, reconnect with validated auth, stop.
   - `RuntimeEventSink`: typed lifecycle events; no transport implementation.
   - `AccountSecretPort`: business-service-backed load/save; no direct DB access.
   - `AccountLeasePort`: acquire/renew/release with owner and fencing token.
3. Implement a gateway-owned Redis Lua lease. Acquisition atomically increments
   a fence counter and sets owner/fence/TTL; renew/release compare both values.
   Defaults: 30-second lease, renewal every 10 seconds; env validation enforces
   renew interval below half the TTL.
4. Wrap `zca-js` behind `zca-client.ts` with `selfListen: true`, typed adapters,
   and no dynamic imports. Convert numeric SDK callbacks into Phase-1 events.
5. Implement the per-account runtime state machine:
   `idle → qr_pending|reconnecting → connected → backoff|reauth_required → stopped`.
   Teardown before replacement, increment local epoch, acquire lease before SDK
   login, and attach the listener only after UID verification.
6. Implement bounded QR retry (three expirations per runtime), passive reconnect
   backoff with jitter, and the five-in-five-minutes circuit breaker. Manual QR
   start resets only the local retry breaker after it owns the lease.
7. Implement pool ownership keyed by the discriminated runtime reference
   (`connect_session` during initial QR, `account` after persistence). Duplicate
   commands on the same instance coalesce; commands without the lease return a
   typed `owned_elsewhere` result rather than opening another socket. Serialize
   starts per key, while stop/shutdown can cancel a pending acquire or reconnect
   without waiting for an uncancellable SDK promise.
8. Add `/healthz` (process alive) and `/readyz` (enabled, Redis connected,
   runtime initialized). No command endpoint is added in this phase.
9. Add graceful shutdown and structured metrics/log fields (`accountId`, epoch,
   fence, state, reason) with all secret/QR payloads omitted.

## Refactor

- Keep Zalo-specific SDK translation in this app. Only the generic port/event
  types belong in the SDK/shared contract.
- Do not move the lease into a generic package until a second runtime needs the
  same fenced lifetime ownership contract.
- Keep retry policy pure and deterministic under a fake clock/random source.

## Acceptance Criteria

- [x] Concurrency tests prove one active listener per account across replicas.
- [x] Stale epoch/fence callbacks cannot publish or update state.
- [x] QR and reconnect lifecycle matches the reference behavior without its
  direct-DB, Socket.IO, or provider-specific business coupling.
- [x] Health, readiness, logging, and graceful shutdown are production-usable.
- [x] The app is disabled by default and has no public/internal command endpoint yet.
- [x] `zca-js` exists only in this app's dependency/import graph.

## Risks and rollback

- Risk: SDK callback or login promise resolves after replacement. Both local
  epoch and distributed fence are checked before every state/event effect.
- Risk: Redis partition creates overlapping owners. The old owner stops when
  renewal fails; downstream item-5 consumers must reject stale fence values.
- Risk: unofficial SDK breaks. Exact pin and adapter tests isolate replacement.
- Rollback: disable the app, stop the deployment, and allow lease TTLs to expire.
  No current channel is registered, so existing traffic is unaffected.
